## 1. Overview

The repository holds no game code yet, so this release also creates the Unity project and its verification
tooling. The valley is one fixed heightfield authored as constant data in `Murim.Core`: a grid of vertex heights,
a grid of cell kinds, a grid of ground cover and a list of large props. Core owns every rule (walkability,
routing, altitude layers, floor view, camera bounds, pause and focus handling) and advances on a fixed 60 Hz
tick. `Murim.View` builds the terrain mesh from the same data, draws every prop as an upright painted sprite,
reads input and applies Core state to a fixed-angle orthographic camera. Floor slicing is one global clip height
shared by all world shaders, with a short fade done inside those shaders.

Compatibility: nothing exists to break; there are no saves, older configs or dev commands. External surfaces: no
networking, accounts, telemetry, save data or mod surface. The only untrusted input is two tunable JSON files
under `Assets/StreamingAssets/Data/` (each at most 64 KiB with an integer `schemaVersion`; anything malformed
falls back to built-in defaults). The valley layout is compiled-in constant data, not a file. Game logs record
event names, file names and field names only: no local paths, user names or machine names. Every game log
line starts with `[Murim]`, which separates it from the engine's own player log lines. One developer control
exists (`F3` navigation overlay); it is compiled only into the Editor and Development builds and is absent from
the release build.

## 2. Conventions and shared contracts

- **Units and coordinates:** 1 world unit = 1 metre. `+x` east, `+y` up, `+z` north. The valley spans
  `x ∈ [0, 160]`, `z ∈ [0, 96]`. Cell `(cx, cz)` covers `[cx, cx+1] × [cz, cz+1]`; there are 160 × 96 cells and
  161 × 97 height vertices. Each cell is two triangles split along the diagonal from `(cx, cz)` to
  `(cx+1, cz+1)`; Core height queries and the View mesh use the same split.
- **Camera frame:** orthographic, rotation Euler `(45, 0, 0)`, never changed at runtime. Core uses the literal
  constants `Sin45 = Cos45 = 0.70710678f` and `Sqrt2 = 1.41421356f`; it calls no trigonometric functions.
- **Simulation tick:** `TickSeconds = 1f / 60f`. The View accumulates unscaled frame time (clamped to 0.1 s per
  frame), runs at most 6 ticks per frame and renders the placeholder interpolated between the previous and
  current tick positions.
- **Determinism rules:** Core uses `float` with `+ − × ÷` and `MathF.Sqrt` only, no random numbers, no clock, no
  threads. Every tie is broken by the lower cell index `cz × 160 + cx`. The same command sequence applied at the
  same ticks yields bit-identical state.
- **Core types:** `Murim.Core` defines its own `Vec2` and `Vec3` structs; it has no `UnityEngine` reference
  (`"noEngineReferences": true`).
- **Unity layers:** `WorldLayer = 6`, `OverlayLayer = 7`, `UiLayer = 5`, declared as constants in
  `Murim.View.Layers` and referenced by index.
- **Configuration loading:** `Assets/StreamingAssets/Data/exploration.json` and `presentation.json`, each at
  most 64 KiB (`65536` bytes) with integer `schemaVersion: 1`. The View checks the size, reads the fixed file
  name (no path comes from input) and parses with `JsonUtility` into a plain DTO with no field initialisers.
  Core `TuningSanitizer` then validates it (one shared range-check helper serves both files). A missing, oversized or malformed file, or a `schemaVersion` other
  than `1`, logs one warning naming the file and uses all built-in defaults. A single field outside its range
  logs one warning naming the file and field and uses that field's default. Ranges and defaults are in §3.9.
- **Developer controls:** `F3` toggles the navigation overlay (§3.10). Its script is wrapped in
  `#if UNITY_EDITOR || DEVELOPMENT_BUILD`; the release build script passes `BuildOptions.None`, so the overlay
  is disabled in release builds.
- **Shader globals:** `_MurimCutY` (target clip height), `_MurimCutYFrom` (previous clip height),
  `_MurimCutFade` (0 → 1), `_MurimAmbientTime` (seconds), `_MurimHeightTex` (161 × 97 `RFloat`, point
  filtered, vertex `(i, j)` at UV `((i + 0.5) / 161, (j + 0.5) / 97)`), `_MurimSurfaceTex0` and
  `_MurimSurfaceTex1` (160 × 96 `RGBA32` surface weights). The View sets them; shaders never read `_Time`.
- **Game logs:** all game logging goes through `Murim.View.GameLog`, which prefixes `[Murim]` and accepts only
  an event name plus file and field names.

### 2.1 Core vertical model

| Constant | Value |
|---|---|
| `FloorHeight` | 3 m |
| Ground floors | 4: `Ground Floor 1` at 0 m, `2` at 3 m, `3` at 6 m, `4` at 9 m |
| `BandOf(y)` | `min(5, floor(y / 3) + 1)`; bands 1–4 are the ground floors, band 5 (`y ≥ 12`) is above every floor |
| Air layers | 3 absolute altitudes: `Air Layer 1` 5 m, `2` 11 m, `3` 17 m |
| `MinAirClearance` | 1.5 m |
| `MaxWalkEdgeDelta` | 0.5 m per cell edge |
| `MinCliffEdgeDelta` | 1.5 m per cell edge |
| Air bounds | `x ∈ [8, 152]`, `z ∈ [4, 89]` for the authored valley; a property of each layout (`ValleyLayout.AirBounds`). A cell is inside when its centre is inside |
| Viewed floor `CutY` | Full View: `+∞`; floor `n`: `3n − 0.02` (2.98, 5.98, 8.98, 11.98) |
| North back row | Every vertex on row `z = 96` is 13 m. Nothing with `z ≥ 90` is ever sliced, by shaders or by the raycaster |
| `LogicalHeight` | On foot: `HeightAt(Position)`. Airborne: the altitude of `AirLayer`. It changes on the tick of the input, before `Elevation` catches up |
| `LogicalBand` | `BandOf(LogicalHeight)` |

Air layers sit between floor heights on purpose: each clears the floor below it by at least 2 m, so an airborne
placeholder is never flush with a terrace. `Air Layer 3` is 4 m above the highest terrain (13 m) and 2 m above
the bamboo tops (15 m).

## 3. Feature design

### 3.1 Valley layout data (F-01, F-02, F-03, F-04)

**Ownership.** `Assets/Scripts/Core/Valley/`: `ValleyLayout` (immutable, queries), `ValleyLayoutData` (the
authored constant), `ValleyLayoutParser`, `ValleyRaycaster`, `ValleyConstants`.

**Encoding.** `ValleyLayoutData` holds four members, authored by hand as row strings, row 0 = `z = 0`:

| Member | Shape | Meaning |
|---|---|---|
| `Heights` | 97 strings × 161 chars | Vertex height in 0.5 m steps: `0`–`9` = 0–4.5 m, `a`–`z` = 5–17.5 m. Maximum authored value `q` (13 m). |
| `Cells` | 96 strings × 160 chars | Cell kind, table below. |
| `Cover` | 96 strings × 160 chars | Ground cover: `.` none, `a` short meadow cover, `t` taller edge tufts, `k` sparse rocky tufts, `w` white flowers, `y` yellow flowers. |
| `Props` | array of `(kind, cx, cz, flipX)` | Large props, placed at the cell centre. |

`ValleyLayoutParser.Parse` also accepts smaller grids for tests and throws `LayoutFormatException` on a wrong
row length, an unknown character or a broken structural invariant below.

| Kind | Meaning | On foot | Obstacle height |
|---|---|---|---|
| `m` `e` `g` `d` | Meadow, exposed earth, exposed granite, damp bank | Walkable | 0 |
| `s` `r` | Earthen slope, rocky slope | Walkable | 0 |
| `c` | Cliff and ridge rock | Impassable | 0 |
| `k` | Wet rock beside the waterfall | Impassable | 0 |
| `b` | Dense bamboo grove | Impassable | 6 m |
| `w` `v` | River channel, river riffle | Impassable | 0 |
| `f` | Waterfall cascade | Impassable | 0 |

| Prop kind | Blocks cells whose centre is within | Obstacle height | Allowed on |
|---|---|---|---|
| `BoulderUpright` | 0.9 m | 2.0 m | walkable kinds |
| `BoulderSquat` | 1.3 m | 1.5 m | walkable kinds |
| `BoulderLow` | 0.9 m | 1.0 m | walkable kinds |
| `PineUpright`, `PineLeaning`, `PineSpreading` | 0.6 m | 8, 7, 6 m | walkable kinds, `c` |
| `ShrubRound`, `ShrubSpreading` | none | 0 | walkable kinds |
| `CliffCrest`, `CliffToe` | none | 0 | `c`, `k` |
| `RiverRocks` | none | 0 | `w`, `v` |
| `FallFoam` | none | 0 | `w`, `v`, `f` |

**Derived per cell at parse time.** `Walkable` = walkable kind, no blocking prop, and all four cell edges have a
height difference ≤ 0.5 m. `FlatFloor` = walkable, not a slope kind, and all four corners within 0.5 m above a
floor height; its floor number is that floor. `SolidTop` = highest corner height + obstacle height. `Component`
= connected component label over walkable cells, 8-neighbour, a diagonal step allowed only when both orthogonal
neighbours are walkable.

**Structural invariants (checked by `Parse` on every layout, including test fixtures).** Row lengths and
characters are valid. A walkable-kind cell has no edge difference above 0.5 m, so every steeper cell is an
impassable kind. Every prop sits on an allowed kind. The start cell is walkable.

**Authored invariants (checked by `ValleyLayoutRules.CheckAuthored`, run by tests on `ValleyLayoutData`
only).** All vertices on row `z = 0` are 0 m and all cells on row 0 are `w` or `v`. All vertices on row `z = 96`
are 13 m. No walkable cell lies outside `x ∈ [16, 144)`, `z ∈ [12, 90)`. `SolidTop ≤ 15.5 m` everywhere inside
the air bounds. Explicit props ≤ 400; cover cells ≤ 4000.

**Blockout.** The author follows this table. Where rectangles overlap, the later row wins. Region edges may
wander up to 2 cells from the listed rectangle to read as natural; slope footprints, elevations and the minimums
below are exact. Rectangles are `x0–x1 × z0–z1` in metres. Every cell of the valley falls in at least one row.

**Slope shoulders.** A slope footprint has one height per row across its width. The column of cells on each
side of it is its shoulder: the vertices on the slope side take the slope height and the vertices on the far
side take the surrounding terrain height. A shoulder cell whose four edges all differ by ≤ 0.5 m takes the
slope's kind and is walkable; any other shoulder cell is `c`. This is what joins a slope to the floors and
cliff bands beside it.

Minimum prop counts: ≥ 24 pines and ≥ 18 boulders with every variant used at least 4 times, ≥ 20 shrubs. No
blocking prop on a slope cell or within 3 cells of the start. Placeholder start: centre of cell `(70, 28)`, on
foot. The valley is 160 m wide against a 40 m default view, 4.0 default screen widths (F-01).

**Queries.** `HeightAt(x, z)` (triangle interpolation), `KindAt`, `IsWalkable`, `ComponentOf`,
`SolidTop(cx, cz)`, `SurfaceAt(x, z)` = `HeightAt(x, z)` + the cell's obstacle height (the visible surface
directly below a point), `AirBounds`, and `IsAirClear(cx, cz, layer)` = inside the air bounds and
`altitude(layer) ≥ SolidTop + 1.5`.
`ValleyRaycaster.Raycast(origin, dir, cutY)` walks cells along the ray and returns the first of: `Ground`
(a triangle whose hit point has `y ≤ cutY`, or any height where `z ≥ 90`), `Cap` (the plane `y = cutY` where
the terrain is above it and `z < 90`) or `None`. Sprites are never hit, so a click passes through foliage to the ground behind.

### 3.2 Placeholder movement on foot (F-06, CE-8, EC-5, EC-10, EC-12)

**Ownership.** `Assets/Scripts/Core/Exploration/Placeholder/`: `PlaceholderState`, `PlaceholderController`,
`GridPathfinder`.

State: `Position (x, z)`, `Elevation`, `AirLayer` (0 = on foot, 1–3), `TargetElevation`, the remaining path and
`Motion`, one of `GroundedStationary`, `GroundedTranslating`, `AirborneStationary`, `AirborneTranslating`,
`Ascending`, `Descending`.

`Click(rayOrigin, rayDir, cutY)` while on foot (`AirLayer = 0`, including during a landing):

1. `P` = raycast hit. If `P` is `Ground`, its cell is walkable and in the placeholder's component, the target is
   `P` and the marker is `Reachable`.
2. Otherwise `Q` = the ray's intersection with the plane `y = (LogicalBand − 1) × 3`. The candidates are the
   placeholder's current cell plus every `FlatFloor` cell of floor `LogicalBand` in its component; slope cells
   are never candidates, so a blocked click cannot carry the placeholder to another floor. Pick the candidate
   whose centre is closest to `Q` (squared distance, ties by lower index). The target is `Q` clamped into that
   cell. The marker is `Unreachable`. If the chosen cell is the current cell and the target is within 0.05 m,
   the placeholder stays put.
3. Either target is then inset 0.3 m from every edge of its cell that borders a non-walkable cell, so the
   capsule never overlaps a cliff, boulder or bank.
4. The marker is shown at `P` when the ray hit anything, else at `Q`. A `Cap` hit counts as not reachable.

Routing is A* over walkable cells (8-neighbour, costs 10 and 14, octile heuristic, ties by lower `f`, then lower
`h`, then lower index), followed by greedy line-of-sight simplification: a waypoint is skipped when the straight
segment and its two parallels offset ± 0.3 m touch only walkable cells. Working arrays are allocated once at
160 × 96. Each tick the placeholder advances `walkSpeed × TickSeconds` along the path; `Elevation =
HeightAt(Position)`; when the remaining distance is within one step plus 0.0001 m it snaps to the target. A new click replaces the path and the marker immediately (EC-10). The placeholder changes
height on foot only by following the terrain (EC-12).

### 3.3 Altitude layers and airborne movement (F-03, F-06, CE-9, CE-10, EC-6, EC-7, EC-8, EC-14)

**Ascend (`R`).** On foot: the target is the lowest layer with altitude ≥ `LogicalHeight + 1.5` that is
air-clear over the current cell. Airborne: the next layer up if it is air-clear. If none qualifies the state is unchanged.

**Descend (`F`).** Airborne at layer `k`: if layer `k − 1` exists and is air-clear over the current cell, move
to it. Otherwise, if the current cell is walkable, land: `AirLayer = 0`, target elevation
`HeightAt(Position)`, which is the slope surface over a slope (EC-14). Otherwise the state is unchanged, which
leaves the placeholder at the lowest clear layer above water, cliffs, boulders, trunks and bamboo (EC-7). On
foot: unchanged.

Both inputs always emit a label event, including when nothing changed (EC-6), and always cancel the current
destination. `AirLayer` changes at once; `Elevation` then moves toward the target at `verticalSpeed`, with
`Motion` `Ascending` or `Descending`, and horizontal movement waits until it arrives. Repeated presses retarget
from the logical layer, so rapid input never overshoots.

**Airborne click.** The target is the ray's intersection with the plane `y = altitude(AirLayer)`. The
placeholder moves in a straight line at `airSpeed` and stops 0.3 m before the first cell that is not air-clear
at its layer (never behind its starting point), which covers both taller terrain and the air bounds (EC-8). The marker sits at the target on the
layer plane: `Reachable` if the whole segment is clear, else `Unreachable`.

**Interrupt.** `Interrupt()` (menu open or focus loss) clears the destination. A layer change in progress is
not cancelled: `Elevation` holds where it is while the session is paused or unfocused and continues to
`TargetElevation` once ticks resume (owner decision, 2026-11-28).

Worked ladder at the start cell (ground 0 m): `R` → 5 m, `R` → 11 m, `R` → 17 m, `R` → unchanged with label;
`F` → 11 m, `F` → 5 m, `F` → lands at 0 m. Over the Floor 4 strip at 11 m: layer 1 fails (5 < 9 + 1.5), so `F`
lands at 9 m. Over the river at 5 m: `F` is unchanged.

### 3.4 Floor view and slicing (F-03, F-05, CE-4, CE-5, EC-9, EC-13)

**Ownership.** Core `FloorView` in `Assets/Scripts/Core/Exploration/Session/`; View `CutawayController` in
`Assets/Scripts/View/World/`.

`ViewedFloor` is `0` (Full View) or `1`–`4`. `StepDown`: Full View → 4 → 3 → 2 → 1, then stays. `StepUp`:
1 → 2 → 3 → 4 → Full View, then stays. Both always emit a label event.

The placeholder is visible when `ViewedFloor = 0` or `LogicalBand ≤ ViewedFloor`. `EnsureVisible()` does
nothing when it is visible. Otherwise it sets `ViewedFloor = LogicalBand` when that band is 1–4, or Full View
when it is 5. It runs on `Space`, and on `R` and `F` after the layer has changed. During a walk it runs only on
a tick where the placeholder was visible before the tick and would be hidden after it, and emits no label
(EC-13). A placeholder the player has deliberately sliced away stays hidden until `PageUp`, `Space`, `R`, `F`
or `Home`. Because visibility follows `LogicalBand`, an ascent raises the view on the press and a descent never
lowers it.

**Rendering.** Every world shader discards fragments with world `y > _MurimCutY`, except where `z ≥ 90`. The
shadow pass applies the same clip, so sliced geometry casts no shadow. A cap quad covering the valley at
`y = _MurimCutY` draws only where the terrain is above the cut; the cap shader reads the four corner texels of
`_MurimHeightTex` and evaluates the same two-triangle interpolation as Core, so cap and terrain meet exactly.
The cap uses the ART-002 exposed-earth tile where the surface weights are meadow, earth, damp or earthen slope,
and the ART-003 cliff-face tile elsewhere, so cut terrain reads as solid ground. The capsule and its height cue
ignore the clip; they are shown or hidden whole by the rule above.

**Fade (art option 8A).** `CutawayController.SetCut(cutY)` sets `_MurimCutYFrom` to the old value,
`_MurimCutY` to the new one and runs `_MurimCutFade` from 0 to 1 over `cutFadeSeconds`. Fragments between the
two heights are drawn with coverage `1 − fade` when the cut is lowering and `fade` when it is rising, through
alpha-to-coverage; during a fade the cap is drawn at both heights, the new one with coverage `fade`. The world
stays live, so panning, zooming and walking during a fade leave no ghost. A new change during a fade first
completes the current one at once. The capsule and cue fade in or out over the same time when their visibility
changes.

### 3.5 Camera (F-05, CE-1, CE-2, CE-3, CE-6, CE-7, EC-1, EC-2, EC-3)

**Ownership.** Core `CameraModel` in `Assets/Scripts/Core/Exploration/Session/`; View `CameraRig` in
`Assets/Scripts/View/Exploration/`.

State: `Focus (x, z)` on the plane `y = 0` and `OrthoSize` (half the visible height in metres). With
`halfH = OrthoSize` and `halfW = OrthoSize × aspect`, `Clamp(aspect)` runs after every change:

- `OrthoSize ∈ [minOrthoSize, min(maxOrthoSize, 160 / (2 × aspect), 96 / (2 × Sqrt2))]`
- `Focus.x ∈ [halfW, 160 − halfW]`
- `Focus.z ∈ [halfH × Sqrt2, 109 − halfH × Sqrt2]`

A point at `(z, y)` appears where ground at `z + y` would, so the screen spans `z + y` from
`Focus.z − halfH × Sqrt2` to `Focus.z + halfH × Sqrt2`. The bottom edge meets the ground at `z ≥ 0`, where the
layout is always river at 0 m. The top edge reaches `z + y = 109`, the top of the 13 m back row at `z = 96`,
which is never sliced; a ray passing `z = 96` at or below 13 m has already hit terrain. So no void is ever
visible (EC-1), and the whole crest, the grove and a capsule at `Air Layer 3` on the north air bound
(`89 + 17 = 106`) are all reachable by the view. Clamping is a hard limit with no
easing, so there is no bounce.

| Input | Rule |
|---|---|
| Pan keys | Direction = (right − left, up − down); opposing keys cancel (EC-2); diagonals are normalised. Screen speed `v = panSpeed × 2 × OrthoSize` m/s. `Focus.x += dir.x × v × dt`, `Focus.z += dir.y × v × dt × Sqrt2`, where `dt` is the unscaled frame time clamped to 0.1 s. |
| Drag (right or middle button) | `mpp = 2 × OrthoSize / screenHeightPx`. `Focus.x −= dxPx × mpp`, `Focus.z −= dyPx × mpp × Sqrt2`, which keeps the grabbed ground point under the cursor. While a drag is active, pan keys are ignored; when it ends they apply again from the current focus (EC-3). |
| Scroll | A frame whose `Mouse.current.scroll.y` is non-zero is one notch in the direction of its sign, whatever its size. Each notch multiplies `OrthoSize` by `1 / zoomStep` (in) or `zoomStep` (out), applied at once about the screen centre. |
| `Space` | `Focus = (p.x, p.z + p.y)` for placeholder position `p`, then `EnsureVisible()`. One-shot; the camera does not follow. |
| `Home` and `Reset View` | `Focus = defaultFocus`, `OrthoSize = defaultOrthoSize`, `ViewedFloor = 0`. The placeholder is untouched. |

Camera inputs are applied once per rendered frame, not per simulation tick, so panning and dragging stay
smooth at any refresh rate. The View places the camera at `(Focus.x, 84.85, Focus.z − 84.85)` (120 m back along the view direction), near
plane 1, far plane 300.

### 3.6 Session, pause and focus (F-07, CE-11, CE-12, CE-13, CE-14, CE-15, EC-4, EC-11)

**Ownership.** Core `ExplorationSession` in `Assets/Scripts/Core/Exploration/Session/` composes the layout,
placeholder, floor view and camera model and is the only type the View calls for rules.

- `Paused` is true while the menu is open. `OpenMenu()` calls `Interrupt()`, ends any drag, disarms the pan
  keys and hides the label and marker. While paused every exploration input method returns without effect.
  `Tick()` does nothing while paused or unfocused, so the placeholder holds its exact position, including
  part-way through a layer change.
- `Resume()` clears `Paused` and nothing else; the cancelled move stays cancelled and a held layer change
  finishes. `ResetViewFromMenu()` resets
  the view as `Home` does, then resumes.
- `SetFocused(false)` calls `Interrupt()`, ends any drag and disarms the pan keys. A pan direction is armed
  again only by a key-down edge; a drag starts only on a button-down edge. So on refocus nothing moves without
  fresh input, except a layer change that was already under way.
- `AmbientRunning = !Paused`. Focus does not affect it. The player setting `runInBackground` and
  `visibleInBackground` are on so the ambient clock keeps running, visibly, while unfocused.
- World clicks act on the button-down edge. A menu button acts on release, and its press happened while paused,
  so no click reaches the valley.
- Feedback is polled, not pushed: `Label { Kind (FullView, GroundFloor, AirLayer), Index, Sequence }` and
  `Marker { Kind (Reachable, Unreachable), Point, Sequence }`. A new sequence number replaces whatever the View
  is showing, so there is never more than one label or marker (EC-10).

| Input | Label content |
|---|---|
| `PageUp`, `]`, `PageDown`, `[` | The viewed floor: `Full View` or `Ground Floor N` |
| `R` | `Air Layer N` of the placeholder after the input |
| `F` | `Air Layer N`, or `Ground Floor N` (band of the landing height) when it lands or is on foot |
| Anything else, including slope walks, `Space` and `Home` | No label |

### 3.7 World rendering and atmosphere (F-02, F-08)

**Ownership.** `Assets/Scripts/View/World/` and `Assets/Shaders/`.

| Component | Contract |
|---|---|
| `TerrainMeshBuilder` | One mesh, 15 617 shared vertices, 30 720 triangles, heights from Core. Generates `_MurimHeightTex` and the two surface-weight textures (bilinear, one texel per cell: channels meadow, earth, granite, damp; then earthen slope, rocky slope, wet rock, cliff). |
| `MurimTerrain` shader | Blends the six ground tiles by surface weight, world-space UV at 8 m per repeat. Named pairs (meadow–earth, earth–granite, meadow–granite) sharpen the blend with their mask tile; other adjacent pairs blend linearly. `c` and `k` weight uses the cliff-face or wet-rock tile projected on the vertical plane facing the normal where the geometric normal (from screen derivatives) has `y < 0.6`, and the exposed-granite tile top-down elsewhere. Lambert with shadows. |
| `PropMeshBuilder` | One combined mesh per 32 × 32-cell block. Each prop or cover card is an upright quad facing `−z`, its pivot at ground height on the cell centre, sized from its sprite at 128 px per metre with the height multiplied by `Sqrt2` so it shows at painted proportions under the 45° camera; a pixel `p` above the pivot is at world height `p / 128 × Sqrt2` above the ground, which is what the cut compares. `CliffCrest` stands at its cell's highest corner height and `CliffToe` at its lowest. Bamboo: one clump per `b` cell; the lower edge clump where the cell to the south is not `b`, otherwise upright or leaning by `(cx × 7 + cz × 13) mod 2`. Cover: `a` draws 2 cards, the others 1, at offsets from a fixed 8-entry table indexed by `(cx × 7 + cz × 13) mod 8`. |
| `MurimProp` shader | Samples the prop atlas, alpha clip at 0.5 with alpha-to-coverage. In the colour pass every vertex is moved 0.7 m toward the camera along the view direction (`SpriteDepthBias`), so the up to 40 px a sprite paints below its pivot draws over the ground in front instead of being hidden by it; all sprites share the bias, so their order among themselves is unchanged. It casts and receives shadows with a fixed light term, clips at `_MurimCutY`. Sway: horizontal offset `amplitude × weight × wave(_MurimAmbientTime / period + phase)`, where `weight` rises from 0 at the pivot to 1 at the sprite top (pines: 0 below 35 % of the height, so trunks stay fixed) and `phase` comes from an integer hash of the cell. `wave` is a triangle wave smoothed by `3t² − 2t³`. |
| `WaterMeshBuilder`, `MurimWater` shader | Quads over `w`/`v` cells at terrain height + 0.02 m. Opaque flow tile scrolling toward `−x`; riffle tile over `v` cells at twice the speed; shoreline strip within 1 m of a non-water cell, its inner edge broken up by the damp–river mask tile in world space. `RiverRocks` and `FallFoam` are flat decals on the water surface; each `FallFoam` scales by ± 5 % on a 1.2 s cycle of the ambient clock. |
| `MurimWaterfall` shader | Ribbon mesh over `f` cells, offset 0.05 m along the normal, scrolling downward. |
| Lighting | `WorldView.Build` creates one directional light, rotation Euler `(50, 35, 0)`, colour `#FFF8EE`, intensity 1.1, soft shadows at strength 0.6, and sets flat ambient `#8E9AA6`. The pipeline asset (ARCH-001) sets one cascade, a 4096 map, shadow distance 180, Linear colour space, MSAA 4×, no post-processing, no fog. |
| `AmbientClock` | Adds unscaled frame time (clamped to 0.1 s) to `_MurimAmbientTime` while `AmbientRunning`; otherwise holds the value, which freezes every family in its current pose. |

Lighting is neutral daylight, as selected in art option 2B and required by ART-013 (no golden haze). This
satisfies the "daytime" reading of F-08 and release check 10.

Cost: about 31 k terrain triangles, at most 10 k prop quads in 15 meshes, under 60 draw calls, no per-frame
allocation. Routing on a click visits at most 15 360 cells.

## 4. Art delivery contracts

Every art file is a flat 2D painting: **no 3D model file of any kind is delivered or accepted**. Files go under
`Assets/Resources/Art/` with exact names. Credit each family in `Assets/Art/ART_README.md`. The owner obtains
and commits production art; nothing from `docs/references/` ships. Integration ticket for every item below:
ARCH-007, except where a heading names another ticket.

**Common rules for all art (ART-001–ART-021).**

- **Scale.** World sprites: 128 pixels = 1 metre of screen plane, painted as seen from the 45° game camera
  under neutral daylight (2B). Ground tiles: 128 pixels = 1 metre of ground, painted top-down.
- **Format.** PNG, 8 bits per channel, sRGB, straight alpha where RGBA, exact pixel sizes as listed.

**Seamless tile rules.** RGB unless a row says RGBA, tiles without a visible seam on all four edges, no single
feature that would make the repeat obvious at the widest zoom. Import: texture type Default, sRGB on, mipmaps
on, Trilinear, wrap Repeat, compression High Quality, max size 2048.

**Sprite rules.** RGBA with a fully transparent background (alpha 0, no matte or halo); the outer 4 pixels of
the canvas are fully transparent; the canvas and pivot are exactly as listed, with the pivot given in pixels
from the bottom-left corner at the centre of the line where the object meets the ground. Only the contact
shadow and the near edge of the footprint may be painted below the pivot row, which is never more than 40 px
up the canvas. "Top" is the allowed height of the highest opaque pixel above the pivot row and is what the
painter works to; it is about 0.71 × the logical height × 128 px plus the visible depth of the object's top.
"Logical height" is the height the game rules use and is given for scale only. Import: texture type Sprite (2D
and UI), Single, 128 pixels per unit, custom pivot, Full Rect mesh, Read/Write on, mipmaps on, Trilinear, wrap
Clamp, alpha is transparency, compression High Quality, max size 2048.

**Sprite atlas (built at load, ARCH-005).** No atlas file is delivered or committed. `ArtCatalog` packs every
world sprite into one page of at most 4096 × 4096 with 8 px padding when the valley loads (§3.8).

## 8. Risks and technical decisions

| Topic | Decision and reason |
|---|---|
| Layout as compiled data | The valley is constant data in Core rather than a JSON file. It is fixed content, not a tunable; this guarantees the same place on every launch, removes a file that would otherwise need a built-in duplicate as its fallback, and keeps layout out of the untrusted-input surface. Cost: changing the layout needs a rebuild. |
| Heightfield terrain | One height per vertex cannot express overhangs. None are required, and a 3 m rise across one cell reads as a sheer face at 45°. |
| Painted sprites on upright quads | Matches the approved painted look and the owner's 2D art sourcing, depth-sorts correctly against terrain and clips at a true world height. Risk: a prop cannot be seen from another angle, which the fixed camera never needs. |
| Shader fade for slicing | The fade runs inside the world shaders through alpha-to-coverage, so the world stays live and nothing ghosts when the camera or capsule moves. Risk: with 4× MSAA the fade has five coverage steps and may look stepped; accepted for a 0.25 s fade, tunable through `cutFadeSeconds`. |
| Sprite depth bias | All upright sprites draw 0.7 m nearer the camera so painted ground contact is not cut off. Risk: a sprite within 0.7 m behind a terrain edge can show through it; props are kept off cliff rims by the layout. |
| Fixed 60 Hz tick | Makes movement independent of frame rate and repeatable across launches. |
| Three air layers at 5, 11, 17 m | Fewest layers that clear each cliff tier and sit clearly above the ridge and bamboo. |
| Altitude input and interruption | `R`/`F` cancel the current destination. Opening the menu or losing focus cancels the destination but holds a layer change in mid-air and finishes it afterwards (owner decision). |
| Lighting | Neutral daylight per art option 2B and ART-013, within the "daytime" wording of F-08 and release check 10. |
| Defaults open to the owner | Player-visible choices made here that the product spec leaves open: label text `Full View`, `Ground Floor N`, `Air Layer N`; `R`/`F` cancelling a walk; the menu hiding the label and marker when it opens; a click on cut terrain counting as unreachable; the Lone terrace and Hidden glade as air-only spots. |
| Art arrives after code | Stand-in art keeps tests and builds running; the `art` suite blocks release until every §4 file is present. |
| Trust boundaries | Untrusted input is limited to the two files under `Assets/StreamingAssets/Data/`: fixed names, 64 KiB cap, `schemaVersion` check, typed parsing, per-field range checks, defaults on any failure. No networking, save data or command-line flags. |
| Logs and privacy | Game logs record event names, file names and field names only; no local paths, user or machine names. Verified by T-ENG-17 and T-BLD-02. |
| Dependencies | Four Unity packages and three NuGet packages, all at exact versions with lock files committed. The Unity package versions are whatever editor `6000.3.29f1` resolves at ARCH-001, then frozen. The editor, SDK `10.0.404` and NuGet versions have not been verified together; if they do not restore or build, ARCH-001 reports back rather than substituting versions. |
