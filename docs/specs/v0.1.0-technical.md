## 1. Overview

The repository holds no game code yet, so this release also creates the Unity project and its verification
tooling. The valley is one fixed heightfield authored as constant data in `Murim.Core`: a grid of vertex heights,
a grid of cell kinds, a grid of ground cover and a list of large props. Core owns every rule (walkability,
routing, altitude layers, floor view, camera bounds, pause and focus handling) and advances on a fixed 60 Hz
tick. `Murim.View` builds the terrain mesh from the same data, draws every prop as an upright painted sprite,
reads input and applies Core state to a fixed-angle orthographic camera. Floor slicing is one global clip height
shared by all world shaders, with a short screen cross-fade.

Compatibility: nothing exists to break; there are no saves, older configs or dev commands. External surfaces: no
networking, accounts, telemetry, save data or mod surface. The only untrusted input is two tunable JSON files
under `Assets/StreamingAssets/Data/` (each at most 64 KiB with an integer `schemaVersion`; anything malformed
falls back to built-in defaults). The valley layout is compiled-in constant data, not a file. Game logs record
event names, file names and field names only: no local paths, user names or machine names. One developer control
exists (`F3` navigation overlay); it is compiled only into the Editor and Development builds and is absent from
the release build.

## 2. Conventions and shared contracts

- **Units and coordinates:** 1 world unit = 1 metre. `+x` east, `+y` up, `+z` north. The valley spans
  `x ∈ [0, 160]`, `z ∈ [0, 96]`. Cell `(cx, cz)` covers `[cx, cx+1] × [cz, cz+1]`; there are 160 × 96 cells and
  161 × 97 height vertices. Each cell is two triangles split along the diagonal from `(cx, cz)` to
  `(cx+1, cz+1)`; Core height queries and the View mesh use the same split.
- **Camera frame:** orthographic, rotation Euler `(45, 0, 0)`, never changed at runtime. Core uses the literal
  constants `Sin45 = Cos45 = 0.70710678f` and `Sqrt2 = 1.41421356f`; it calls no trigonometric functions.
- **Simulation tick:** `TickSeconds = 1f / 60f`. The View accumulates unscaled frame time (clamped to 0.1 s per
  frame), runs at most 6 ticks per frame and renders the placeholder interpolated between the previous and
  current tick positions.
- **Determinism rules:** Core uses `float` with `+ − × ÷` and `MathF.Sqrt` only, no random numbers, no clock, no
  threads. Every tie is broken by the lower cell index `cz × 160 + cx`. The same command sequence applied at the
  same ticks yields bit-identical state.
- **Core types:** `Murim.Core` defines its own `Vec2` and `Vec3` structs; it has no `UnityEngine` reference
  (`"noEngineReferences": true`).
- **Unity layers:** `WorldLayer = 6`, `OverlayLayer = 7`, `UiLayer = 5`, declared as constants in
  `Murim.View.Layers` and referenced by index.
- **Configuration loading:** `Assets/StreamingAssets/Data/exploration.json` and `presentation.json`, each at
  most 64 KiB (`65536` bytes) with integer `schemaVersion: 1`. The View checks the size, reads the fixed file
  name (no path comes from input) and parses with `JsonUtility` into a plain DTO with no field initialisers.
  Core `TuningSanitizer` then validates it (one shared range-check helper serves both files). A missing, oversized or malformed file, or a `schemaVersion` other
  than `1`, logs one warning naming the file and uses all built-in defaults. A single field outside its range
  logs one warning naming the file and field and uses that field's default. Ranges and defaults are in §3.9.
- **Developer controls:** `F3` toggles the navigation overlay (§3.10). Its script is wrapped in
  `#if UNITY_EDITOR || DEVELOPMENT_BUILD`; the release build script passes `BuildOptions.None`, so the overlay
  is disabled in release builds.
- **Shader globals:** `_MurimCutY` (clip height), `_MurimAmbientTime` (seconds), `_MurimHeightTex`
  (161 × 97 `RFloat` height texture), `_MurimSurfaceTex0` and `_MurimSurfaceTex1` (160 × 96 `RGBA32` surface
  weights). The View sets them; shaders never read `_Time`.

### 2.1 Core vertical model

| Constant | Value |
|---|---|
| `FloorHeight` | 3 m |
| Ground floors | 4: `Ground Floor 1` at 0 m, `2` at 3 m, `3` at 6 m, `4` at 9 m |
| `BandOf(y)` | `min(5, floor(y / 3) + 1)`; bands 1–4 are the ground floors, band 5 (`y ≥ 12`) is above every floor |
| Air layers | 3 absolute altitudes: `Air Layer 1` 5 m, `2` 11 m, `3` 17 m |
| `MinAirClearance` | 1.5 m |
| `MaxWalkEdgeDelta` | 0.5 m per cell edge |
| `MinCliffEdgeDelta` | 1.5 m per cell edge |
| Air bounds | `x ∈ [8, 152]`, `z ∈ [4, 90]` |
| Viewed floor `CutY` | Full View: `+∞`; floor `n`: `3n − 0.02` (2.98, 5.98, 8.98, 11.98) |

Air layers sit between floor heights on purpose: each clears the floor below it by at least 2 m, so an airborne
placeholder is never flush with a terrace. `Air Layer 3` is 4 m above the highest terrain (13 m) and 2 m above
the bamboo tops (15 m).

## 3. Feature design

### 3.1 Valley layout data (F-01, F-02, F-03, F-04)

**Ownership.** `Assets/Scripts/Core/Valley/`: `ValleyLayout` (immutable, queries), `ValleyLayoutData` (the
authored constant), `ValleyLayoutParser`, `ValleyRaycaster`, `ValleyConstants`.

**Encoding.** `ValleyLayoutData` holds four members, authored by hand as row strings, row 0 = `z = 0`:

| Member | Shape | Meaning |
|---|---|---|
| `Heights` | 97 strings × 161 chars | Vertex height in 0.5 m steps: `0`–`9` = 0–4.5 m, `a`–`z` = 5–17.5 m. Maximum authored value `q` (13 m). |
| `Cells` | 96 strings × 160 chars | Cell kind, table below. |
| `Cover` | 96 strings × 160 chars | Ground cover: `.` none, `a` short meadow cover, `t` taller edge tufts, `k` sparse rocky tufts, `w` white flowers, `y` yellow flowers. |
| `Props` | array of `(kind, cx, cz, flipX)` | Large props, placed at the cell centre. |

`ValleyLayoutParser.Parse` also accepts smaller grids for tests and throws `LayoutFormatException` on a wrong
row length, an unknown character or a broken invariant below.

| Kind | Meaning | On foot | Obstacle height |
|---|---|---|---|
| `m` `e` `g` `d` | Meadow, exposed earth, exposed granite, damp bank | Walkable | 0 |
| `s` `r` | Earthen slope, rocky slope | Walkable | 0 |
| `c` | Cliff and ridge rock | Impassable | 0 |
| `k` | Wet rock beside the waterfall | Impassable | 0 |
| `b` | Dense bamboo grove | Impassable | 6 m |
| `w` `v` | River channel, river riffle | Impassable | 0 |
| `f` | Waterfall cascade | Impassable | 0 |

| Prop kind | Blocks cells whose centre is within | Obstacle height | Allowed on |
|---|---|---|---|
| `BoulderUpright` | 0.9 m | 2.0 m | walkable kinds |
| `BoulderSquat` | 1.3 m | 1.5 m | walkable kinds |
| `BoulderLow` | 0.9 m | 1.0 m | walkable kinds |
| `PineUpright`, `PineLeaning`, `PineSpreading` | 0.6 m | 8, 7, 6 m | walkable kinds, `c` |
| `ShrubRound`, `ShrubSpreading` | none | 0 | walkable kinds |
| `CliffCrest`, `CliffToe` | none | 0 | `c`, `k` |
| `RiverRocks`, `FallFoam` | none | 0 | `w`, `v` |

**Derived per cell at parse time.** `Walkable` = walkable kind, no blocking prop, and all four cell edges have a
height difference ≤ 0.5 m. `SolidTop` = highest corner height + obstacle height. `Component` = connected
component label over walkable cells, 8-neighbour, a diagonal step allowed only when both orthogonal neighbours
are walkable.

**Invariants (parser and tests).** A walkable-kind cell has no edge difference above 0.5 m. No edge anywhere has
a difference strictly between 0.5 m and 1.5 m, so every height change is either a gentle slope or a sheer cliff.
All vertices on row `z = 0` are 0 m and all cells on row 0 are `w` or `v`. No walkable cell lies outside
`x ∈ [16, 144)`, `z ∈ [12, 90)`. `SolidTop ≤ 15.5 m` everywhere inside the air bounds. Explicit props ≤ 400;
cover cells ≤ 4000.

**Blockout.** The author follows this table. Region edges may wander up to 2 cells from the listed rectangle to
read as natural; slope footprints, elevations and the minimums below are exact. Rectangles are
`x0–x1 × z0–z1` in metres.

| Region | Rectangle | Height | Kinds and content |
|---|---|---|---|
| River | 0–160 × 0–12 | 0 | `w`, with 3 riffle patches `v` of ≥ 12 cells each; ≥ 8 `RiverRocks` |
| River bank | 16–126 × 12–15 | 0 | `d` |
| Lower clearing (Floor 1) | 16–124 × 15–43 | 0 | `m`; ≥ 3 broad `e` patches, each ≥ 30 cells and ≥ 4 cells wide in both axes; `g` outcrops near cliffs |
| Plunge pool | 126–144 × 12–34 | 0 | `w`; `d` rim on its west side |
| Waterfall | 132–138 × 34–43 | 0 → 9 | `f`: three 3 m drops at `z` 34, 37, 40, each followed by a 2-cell ledge; source pool `w` at `z` 41–43; 3 `FallFoam`, one at each drop base |
| Waterfall backing | 129–132 and 138–141 × 34–43 | 3–9 | `k` |
| East massif | 124–160 × 12–96, outside the pool and fall | 6–12 | `c` |
| West massif | 0–16 × 12–96 | 6–12 | `c`, ≥ 8 pines on top |
| Cliff bands | 16–124 × 43–45, 24–116 × 61–63, 24–124 × 75–77 | 3 m rise each | `c`, 1–2 cells wide; ≥ 20 `CliffCrest` and ≥ 20 `CliffToe` in total |
| Terrace (Floor 2) | 16–124 × 45–61 | 3 | `m`, `g`, `e` |
| Lone terrace | 28–38 × 49–57 | 6 | `g`, ringed by `c`; not connected by any slope |

| North crest | 0–160 × 90–96 | 11–13 | `c` |
| Slope S1 (1 ↔ 2) | 52–60 × 40–46 | 0 → 3 | `s`, rising 0.5 m per cell northward, 8 cells wide |
| Slope S2 (1 ↔ 2) | 100–106 × 40–46 | 0 → 3 | `r`, 6 cells wide |
| Slope S3 (2 ↔ 3) | 80–86 × 58–64 | 3 → 6 | `r`, 6 cells wide |
| Slope S4 (3 ↔ 4) | 40–46 × 72–78 | 6 → 9 | `s`, 6 cells wide |

Minimum prop counts: ≥ 24 pines and ≥ 18 boulders with every variant used at least 4 times, ≥ 20 shrubs. No
blocking prop on a slope cell or within 3 cells of the start. Placeholder start: centre of cell `(70, 28)`, on
foot. The valley is 160 m wide against a 40 m default view, 4.0 default screen widths (F-01).

**Queries.** `HeightAt(x, z)` (triangle interpolation), `KindAt`, `IsWalkable`, `ComponentOf`,
`SolidTopAt(x, z)` = `max(HeightAt, cell obstacle top)`, and
`IsAirClear(cx, cz, layer)` = inside the air bounds and `altitude(layer) ≥ SolidTop + 1.5`.
`ValleyRaycaster.Raycast(origin, dir, cutY)` walks cells along the ray and returns the first of: `Ground`
(a triangle whose hit point has `y ≤ cutY`), `Cap` (the plane `y = cutY` where the terrain is above it) or
`None`. Sprites are never hit, so a click passes through foliage to the ground behind.

### 3.2 Placeholder movement on foot (F-06, CE-8, EC-5, EC-10, EC-12)

**Ownership.** `Assets/Scripts/Core/Exploration/Placeholder/`: `PlaceholderState`, `PlaceholderController`,
`GridPathfinder`.

State: `Position (x, z)`, `Elevation`, `AirLayer` (0 = on foot, 1–3), `TargetElevation`, the remaining path and
`Motion`, one of `GroundedStationary`, `GroundedTranslating`, `AirborneStationary`, `AirborneTranslating`,
`Ascending`, `Descending`.

`Click(rayOrigin, rayDir, cutY)` while on foot:

1. `P` = raycast hit. If `P` is `Ground`, its cell is walkable and in the placeholder's component, the target is
   the exact point `P` and the marker is `Reachable`.
2. Otherwise `Q` = the ray's intersection with the plane `y = (BandOf(Elevation) − 1) × 3`. Among cells in the
   placeholder's component whose centre height is in the same band, pick the one whose centre is closest to `Q`
   (squared distance, ties by lower index). The target is `Q` clamped into that cell, inset 0.3 m from any edge
   that borders a non-walkable cell. The marker is `Unreachable`. If the chosen cell is the current cell and the
   target is within 0.05 m, the placeholder stays put.
3. The marker is shown at `P` when the ray hit anything, else at `Q`.

Routing is A* over walkable cells (8-neighbour, costs 10 and 14, octile heuristic, ties by lower `f`, then lower
`h`, then lower index), followed by greedy line-of-sight simplification: a waypoint is skipped when the straight
segment and its two parallels offset ± 0.3 m touch only walkable cells. Working arrays are allocated once at
160 × 96. Each tick the placeholder advances `walkSpeed × TickSeconds` along the path; `Elevation =
HeightAt(Position)`; when the remaining distance is within one step plus 0.0001 m it snaps to the target. A new click replaces the path and the marker immediately (EC-10). The placeholder changes
height on foot only by following the terrain (EC-12).

### 3.3 Altitude layers and airborne movement (F-03, F-06, CE-9, CE-10, EC-6, EC-7, EC-8, EC-14)

**Ascend (`R`).** On foot: the target is the lowest layer with altitude ≥ `Elevation + 1.5` that is air-clear
over the current cell. Airborne: the next layer up if it is air-clear. If none qualifies the state is unchanged.

**Descend (`F`).** Airborne at layer `k`: if layer `k − 1` exists and is air-clear over the current cell, move
to it. Otherwise, if the current cell is walkable, land: `AirLayer = 0`, target elevation
`HeightAt(Position)`, which is the slope surface over a slope (EC-14). Otherwise the state is unchanged, which
leaves the placeholder at the lowest clear layer above water, cliffs, boulders, trunks and bamboo (EC-7). On
foot: unchanged.

Both inputs always emit a label event, including when nothing changed (EC-6), and always cancel the current
destination. `AirLayer` changes at once; `Elevation` then moves toward the target at `verticalSpeed`, with
`Motion` `Ascending` or `Descending`, and horizontal movement waits until it arrives. Repeated presses retarget
from the logical layer, so rapid input never overshoots.

**Airborne click.** The target is the ray's intersection with the plane `y = altitude(AirLayer)`. The
placeholder moves in a straight line at `airSpeed` and stops 0.3 m before the first cell that is not air-clear
at its layer, which covers both taller terrain and the air bounds (EC-8). The marker sits at the target on the
layer plane: `Reachable` if the whole segment is clear, else `Unreachable`.

**Interrupt.** `Interrupt()` (menu open or focus loss) clears the destination and sets `Elevation =
TargetElevation`. Nothing is left pending, so nothing resumes without fresh input.

Worked ladder at the start cell (ground 0 m): `R` → 5 m, `R` → 11 m, `R` → 17 m, `R` → unchanged with label;
`F` → 11 m, `F` → 5 m, `F` → lands at 0 m. Over the Floor 4 strip at 11 m: layer 1 fails (5 < 9 + 1.5), so `F`
lands at 9 m. Over the river at 5 m: `F` is unchanged.

### 3.4 Floor view and slicing (F-03, F-05, CE-4, CE-5, EC-9, EC-13)

**Ownership.** Core `FloorView` in `Assets/Scripts/Core/Exploration/Session/`; View `CutawayController` in
`Assets/Scripts/View/World/`.

`ViewedFloor` is `0` (Full View) or `1`–`4`. `StepDown`: Full View → 4 → 3 → 2 → 1, then stays. `StepUp`:
1 → 2 → 3 → 4 → Full View, then stays. Both always emit a label event.

The placeholder is visible when `ViewedFloor = 0` or `BandOf(Elevation) ≤ ViewedFloor`.
`EnsureVisible()` sets `ViewedFloor = BandOf(Elevation)` when that band is 1–4 and above the viewed floor, or
Full View when the band is 5. It runs on `Space`, `R` and `F`. During a walk it runs only on a tick where the
placeholder was visible before the tick and would be hidden after it, and emits no label (EC-13). A placeholder
the player has deliberately sliced away stays hidden until `PageUp`, `Space`, `R`, `F` or `Home`. Descending
never changes the viewed floor.

**Rendering.** Every world shader discards fragments with world `y > _MurimCutY`. A cap quad covering the whole
valley at `y = _MurimCutY` draws only where `_MurimHeightTex` is above the cut, textured with the exposed-earth
or exposed-granite tile chosen from the surface weights, so cut terrain reads as solid ground. The capsule and
its height cue ignore the clip; they are shown or hidden whole by the rule above.

**Fade (art option 8A).** When `CutY` changes, `CutawayController` first renders the world camera once into a
screen-sized render texture with the old value, using URP's single-camera render request, then applies the new
value and draws that texture over the world with alpha going 1 → 0 across `cutFadeSeconds`. A second change
during a fade repeats the capture, so there is only ever one overlay and no residue.

### 3.5 Camera (F-05, CE-1, CE-2, CE-3, CE-6, CE-7, EC-1, EC-2, EC-3)

**Ownership.** Core `CameraModel` in `Assets/Scripts/Core/Exploration/Session/`; View `CameraRig` in
`Assets/Scripts/View/Exploration/`.

State: `Focus (x, z)` on the plane `y = 0` and `OrthoSize` (half the visible height in metres). With
`halfH = OrthoSize` and `halfW = OrthoSize × aspect`, `Clamp(aspect)` runs after every change:

- `OrthoSize ∈ [minOrthoSize, min(maxOrthoSize, 160 / (2 × aspect), 96 / (2 × Sqrt2))]`
- `Focus.x ∈ [halfW, 160 − halfW]`
- `Focus.z ∈ [halfH × Sqrt2, 96 − halfH × Sqrt2]`

The bottom screen edge then meets the ground at `z ≥ 0`, where the layout is always river at 0 m, and every
other view ray ends inside the valley, so no void is ever visible (EC-1). Clamping is a hard limit with no
easing, so there is no bounce.

| Input | Rule |
|---|---|
| Pan keys | Direction = (right − left, up − down); opposing keys cancel (EC-2); diagonals are normalised. Screen speed `v = panSpeed × 2 × OrthoSize` m/s. `Focus.x += dir.x × v × dt`, `Focus.z += dir.y × v × dt × Sqrt2`. |
| Drag (right or middle button) | `mpp = 2 × OrthoSize / screenHeightPx`. `Focus.x −= dxPx × mpp`, `Focus.z −= dyPx × mpp × Sqrt2`, which keeps the grabbed ground point under the cursor. While a drag is active, pan keys are ignored; when it ends they apply again from the current focus (EC-3). |
| Scroll | Each notch multiplies `OrthoSize` by `1 / zoomStep` (in) or `zoomStep` (out), applied at once about the screen centre. |
| `Space` | `Focus = (p.x, p.z + p.y)` for placeholder position `p`, then `EnsureVisible()`. One-shot; the camera does not follow. |
| `Home` and `Reset View` | `Focus = defaultFocus`, `OrthoSize = defaultOrthoSize`, `ViewedFloor = 0`. The placeholder is untouched. |

The View places the camera at `(Focus.x, 84.85, Focus.z − 84.85)` (120 m back along the view direction), near
plane 1, far plane 300.

### 3.6 Session, pause and focus (F-07, CE-11, CE-12, CE-13, CE-14, CE-15, EC-4, EC-11)

**Ownership.** Core `ExplorationSession` in `Assets/Scripts/Core/Exploration/Session/` composes the layout,
placeholder, floor view and camera model and is the only type the View calls for rules.

- `Paused` is true while the menu is open. `OpenMenu()` calls `Interrupt()`, ends any drag, disarms the pan
  keys and hides the label and marker. While paused every exploration input method returns without effect and
  `Tick()` does nothing.
- `Resume()` clears `Paused` and nothing else; the cancelled move stays cancelled. `ResetViewFromMenu()` resets
  the view as `Home` does, then resumes.
- `SetFocused(false)` calls `Interrupt()`, ends any drag and disarms the pan keys. A pan direction is armed
  again only by a key-down edge; a drag starts only on a button-down edge. So nothing moves on refocus without
  fresh input.
- `AmbientRunning = !Paused`. Focus does not affect it. The player setting `runInBackground` is on so the
  ambient clock keeps running while unfocused.
- World clicks act on the button-down edge. A menu button acts on release, and its press happened while paused,
  so no click reaches the valley.
- Feedback is polled, not pushed: `Label { Kind (FullView, GroundFloor, AirLayer), Index, Sequence }` and
  `Marker { Kind (Reachable, Unreachable), Point, Sequence }`. A new sequence number replaces whatever the View
  is showing, so there is never more than one label or marker (EC-10).

| Input | Label content |
|---|---|
| `PageUp`, `]`, `PageDown`, `[` | The viewed floor: `Full View` or `Ground Floor N` |
| `R` | `Air Layer N` of the placeholder after the input |
| `F` | `Air Layer N`, or `Ground Floor N` (band of the landing height) when it lands or is on foot |
| Anything else, including slope walks, `Space` and `Home` | No label |

### 3.7 World rendering and atmosphere (F-02, F-08)

**Ownership.** `Assets/Scripts/View/World/` and `Assets/Shaders/`.

| Component | Contract |
|---|---|
| `TerrainMeshBuilder` | One mesh, 15 617 shared vertices, 30 720 triangles, heights from Core. Generates `_MurimHeightTex` and the two surface-weight textures (bilinear, one texel per cell: channels meadow, earth, granite, damp; then earthen slope, rocky slope, wet rock, cliff). |
| `MurimTerrain` shader | Blends the six ground tiles by surface weight, world-space UV at 8 m per repeat. Named pairs (meadow–earth, earth–granite, meadow–granite, damp–river) sharpen the blend with their mask tile; other adjacent pairs blend linearly. Fragments with normal `y < 0.6`, and `c`/`k` cells, use the cliff-face or wet-rock tile projected on the vertical plane facing the normal. Lambert with shadows. |
| `PropMeshBuilder` | One combined mesh per 32 × 32-cell block. Each prop or cover card is an upright quad facing `−z`, bottom-centre at its pivot on the ground, sized from its sprite at 128 px per metre with the height multiplied by `Sqrt2` so it shows at painted proportions under the 45° camera. Bamboo: one clump per `b` cell; the lower edge clump where the cell to the south is not `b`, otherwise upright or leaning by `(cx × 7 + cz × 13) mod 2`. Cover: `a` draws 2 cards, the others 1, at offsets from a fixed 8-entry table indexed by `(cx × 7 + cz × 13) mod 8`. |
| `MurimProp` shader | Samples the prop atlas, alpha clip at 0.5 with alpha-to-coverage, casts and receives shadows with a fixed light term, clips at `_MurimCutY`. Sway: horizontal offset `amplitude × weight × wave(_MurimAmbientTime / period + phase)`, where `weight` rises from 0 at the pivot to 1 at the sprite top (pines: 0 below 35 % of the height, so trunks stay fixed) and `phase` comes from an integer hash of the cell. `wave` is a triangle wave smoothed by `3t² − 2t³`. |
| `WaterMeshBuilder`, `MurimWater` shader | Quads over `w`/`v` cells at terrain height + 0.02 m. Opaque flow tile scrolling toward `−x`; riffle tile over `v` cells at twice the speed; shoreline strip within 1 m of a non-water cell. `RiverRocks` and `FallFoam` are flat decals on the water. |
| `MurimWaterfall` shader | Ribbon mesh over `f` cells, offset 0.05 m along the normal, scrolling downward. |
| Lighting | One directional light, rotation Euler `(50, 35, 0)`, colour `#FFF8EE`, intensity 1.1, soft shadows at strength 0.6, one cascade, 4096 map, shadow distance 300. Flat ambient `#8E9AA6`. Linear colour space, MSAA 4×, no post-processing, no fog. |
| `AmbientClock` | Adds unscaled frame time (clamped to 0.1 s) to `_MurimAmbientTime` while `AmbientRunning`; otherwise holds the value, which freezes every family in its current pose. |

Lighting is neutral daylight. Features F-08 and release check 10 say "daytime / golden-hour", but the later art
approval selected option 2B and ART-013 forbids golden haze; the later decision governs.

Cost: about 31 k terrain triangles, at most 10 k prop quads in 15 meshes, under 60 draw calls, no per-frame
allocation. Routing on a click visits at most 15 360 cells.

### 3.8 Placeholder and feedback presentation (F-06, F-07)

## 4. Art delivery contracts

Every art file is a flat 2D painting: **no 3D model file of any kind is delivered or accepted**. Files go under
`Assets/Resources/Art/` with exact names. Credit each family in `Assets/Art/ART_README.md`. The owner obtains
and commits production art; nothing from `docs/references/` ships. Integration ticket for every item below:
ARCH-007, except where a heading names another ticket.

**Common rules for all art (ART-001–ART-021).**

- **Scale.** World sprites: 128 pixels = 1 metre of screen plane, painted as seen from the 45° game camera
  under neutral daylight (2B). Ground tiles: 128 pixels = 1 metre of ground, painted top-down.
- **Format.** PNG, 8 bits per channel, sRGB, straight alpha where RGBA, exact pixel sizes as listed.

**Seamless tile rules.** RGB, tiles without a visible seam on all four edges, no single feature that would make
the repeat obvious at the widest zoom. Import: texture type Default, sRGB on, mipmaps on, Trilinear, wrap
Repeat, compression High Quality, max size 2048.

**Sprite rules.** RGBA with a fully transparent background (alpha 0, no matte or halo); the outer 4 pixels of
the canvas are fully transparent; the canvas and pivot are exactly as listed, with the pivot given in pixels
from the bottom-left corner at the point where the object meets the ground. "Top" is the allowed height of the
highest opaque pixel above the pivot row. Import: texture type Sprite (2D and UI), Single, 128 pixels per unit,
custom pivot, Full Rect mesh, mipmaps on, Trilinear, wrap Clamp, alpha is transparency, compression High
Quality, max size 2048.

**Sprite atlas (integration asset, ARCH-007).** `Assets/Resources/Art/Props/WorldProps.spriteatlas` packs every
world sprite into one page: max texture size 4096, padding 8, no rotation, mipmaps on, Trilinear, sRGB,
compression High Quality.

## 8. Risks and technical decisions

| Topic | Decision and reason |
|---|---|
| Layout as compiled data | The valley is constant data in Core rather than a JSON file. It is fixed content, not a tunable; this guarantees the same place on every launch, removes a file that would otherwise need a built-in duplicate as its fallback, and keeps layout out of the untrusted-input surface. Cost: changing the layout needs a rebuild. |
| Heightfield terrain | One height per vertex cannot express overhangs. None are required, and a 3 m rise across one cell reads as a sheer face at 45°. |
| Painted sprites on upright quads | Matches the approved painted look and the owner's 2D art sourcing, depth-sorts correctly against terrain and clips at a true world height. Risk: a prop cannot be seen from another angle, which the fixed camera never needs. |
| Screen cross-fade for slicing | Gives the approved smooth fade (8A) without making terrain and props transparent. Risk: if the camera pans during the 0.25 s fade the old frame slides slightly; accepted as imperceptible. |
| Fixed 60 Hz tick | Makes movement independent of frame rate and repeatable across launches. |
| Three air layers at 5, 11, 17 m | Fewest layers that clear each cliff tier and sit clearly above the ridge and bamboo. |
| `R`/`F` cancel the destination; interruption completes a layer change | Keeps the altitude rules free of half-finished states and guarantees nothing resumes without fresh input. |
| Neutral daylight over "golden-hour" | The later art approval (2B, ART-013) supersedes the earlier wording in F-08 and release check 10. |
| Art arrives after code | Stand-in art keeps tests and builds running; the `art` suite blocks release until every §4 file is present. |
| Trust boundaries | Untrusted input is limited to the two files under `Assets/StreamingAssets/Data/`: fixed names, 64 KiB cap, `schemaVersion` check, typed parsing, per-field range checks, defaults on any failure. No networking, save data or command-line flags. |
| Logs and privacy | Game logs record event names, file names and field names only; no local paths, user or machine names. Verified by T-ENG-17 and T-BLD-02. |
| Dependencies | Four Unity packages and three NuGet packages, all at exact versions with lock files committed. The Unity package versions are whatever editor `6000.3.29f1` resolves at ARCH-001, then frozen. |
